# Windows `--offline` 隐藏窗口运行

## Purpose

为 Windows 版 Godot 增加 `--offline` 启动参数，使编辑器、项目主场景和指定场景在不显示原生窗口的情况下使用正常图形后端运行，并允许通过 Godot 内部渲染结果截图。

现有 `--headless` 选择 headless 显示驱动和 dummy 渲染，不能替代本功能。`--offline` 在本变更中指 hidden-window mode，不表示断网；Godot-MCP 等本地通信必须继续可用。

本变更依据 Godot 4.8-dev、`ca871ccc9c` 的源码调研提出。当前尚未实现或完成 Windows/GPU 实测。

## Scope and acceptance

### 交付范围

- 增加 Windows 专用布尔启动参数 `--offline`，保留现有编辑器、项目及场景启动方式；常规导出模板也能使用，不要求应用启用 C#。
- 保留 HWND、原有渲染目标、图形设备、交换链、消息循环和正常渲染提交路径；在 Windows 后端阻止原生窗口显示、激活和抢焦点，不通过最小化或 `Window.hide()` 实现。
- 隐藏范围包括 Godot 管理的主窗口、浮动窗口和原生子窗口。窗口样式修改、布局恢复和后端初始化回退不能造成闪窗。
- 图形初始化前显式关闭进程执行速度节流，申请 HighQoS；失败时写出错误并非零退出，不在未知策略下继续隐藏运行。正常清理和启动失败均释放本次覆盖。
- 离线编辑器启动的 Godot 游戏/工具子进程及编辑器重启继承此模式。首版不使用编辑器嵌入游戏窗口，改为独立隐藏子进程；显式 `--wid` 与此模式冲突。
- 启动失败不弹系统错误框；原生文件选择请求自动取消，其他原生交互对话框明确返回不支持。不替应用自动确认自绘对话框。
- 实现后使用 [IvanMurzak/Godot-MCP](https://github.com/IvanMurzak/Godot-MCP) 实际验证 `screenshot-viewport`、`screenshot-camera` 和 `screenshot-isolated`，包括图像内容和持续更新，不只检查调用是否成功。

### 可观察验收

1. `--offline --editor --path <project>`、`--offline --path <project>` 和 `--offline --path <project> --scene res://<scene>.tscn` 均使用正常 Windows 显示后端及真实图形渲染后端；非最小化窗口持续具备绘制能力。
2. 从进程启动到退出监控原生窗口显示事件和可见窗口列表，Godot 管理的窗口全程不可见；窗口操作不抢占桌面前台、鼠标或键盘焦点。启动终端本身不属于隐藏对象。
3. 参数冲突、HighQoS 失败及图形初始化失败均给出可诊断错误；应退出的路径非零退出，不显示阻塞错误框。
4. 用同一份改动构建出的 .NET 编辑器，在可见和隐藏模式下连接固定版本 Godot-MCP。三种截图工具均产生可解码、尺寸正确且包含预期对象的 PNG；改变标记或对象后截图随之改变。2D/3D 编辑器 viewport、指定相机和节点隔离语义分别核验。
5. MCP 截图期间窗口仍不可见，不以临时 `ShowWindow`、桌面截图或跳过 MCP 的替代脚本冒充通过。场景进程另有内部截图及绘制/提交验证，不能由编辑器 MCP 的成功代替。
6. 无 `--offline` 的正常显示及已有 `--headless` 行为不回归。

### 边界与非目标

- 首版面向有可用图形设备的 Windows 桌面会话，不承诺无显卡、服务 Session 0、注销或 RDP 断开后的运行。其他平台明确拒绝该参数。
- 支持窗口化、最大化和普通全屏布局；独占全屏不在首版范围，明确拒绝请求。隐藏本身不引入最小化；应用显式最小化仍可触发原有停止绘制语义。
- 不增加新的离屏替代渲染后端，不取消 Present，不新增全局强制重绘、后台 sleep、计时器覆盖、防休眠或优先级提升。Godot 原有电源、限帧和渲染设置仍生效。
- 不承诺隐藏和可见模式具有相同 FPS、Present 等待或 GPU 工作量。HighQoS 不是 GPU 频率或计时器分辨率保证；Vulkan 当前交换链允许裁剪不可见区域。
- MCP 相机/隔离截图工具自身使用 SubViewport 不违反上述限制；限制针对引擎主图形路径，不禁止应用或插件原有的离屏渲染。
- 不承诺 Windows 桌面截图、`PrintWindow`、标题栏或原生对话框截图，不纳入新的引擎截图命令。
- 不修改 Godot-MCP 上游、不永久注册外部 MCP 服务、不把测试插件加入引擎运行时依赖；第三方扩展直接调用 Win32 显示窗口不属于本变更可保证的范围。

交付后补充[当前架构](../../../architecture.md)的启动策略与 Windows 显示边界，新增当前规格描述 `--offline` 的参数、窗口、错误和截图兼容性契约。创建阶段只写目标文档，不将未实现的行为写成当前事实。
