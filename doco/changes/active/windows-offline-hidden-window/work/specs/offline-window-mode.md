# Windows 隐藏窗口运行目标规格

## Scope and current contracts

本文件是 `windows-offline-hidden-window` 的目标契约，尚非当前实现。当前 doco/specs/ 没有相关规格；现有代码由 [main/main.cpp](../../../../../../main/main.cpp) 解析 `--headless`，以 `DisplayServerHeadless` / dummy 渲染实现无图形运行。

新增 `--offline` 保留 Windows 正常图形路径。截图集成验收见 [MCP 截图规格](mcp-screenshot-compatibility.md)。

## Requirements

### R1 参数与平台

- `--offline` 是无值布尔参数，只识别 Godot 引擎参数区。重复传入幂等；`--` 或 `++` 后的同名用户参数既不启用模式，也不向编辑器子进程传播。
- 帮助说明 Windows-only、hidden-window、保留渲染、不代表断网，并区分 `--headless`。
- 编辑器启动、项目主场景、指定场景、普通导出模板支持该参数。未找到项目时，编辑器构建仍沿用原有 Project Manager 回退，其窗口同样受门控；自动化测试使用明确有效项目路径。
- 非 Windows 平台返回不支持并非零退出。不得改变其他参数的未知项、重复项及用户参数规则。
- 与显式 `--headless`、headless 显示后端、dummy 渲染、`--wid` 冲突，不得受参数先后顺序影响。隐含 headless 的工具模式、项目 headless 配置或 dedicated-server 配置同样不得静默混用。
- 支持窗口化、最大化、无边框和普通全屏。初始独占全屏配置使启动/子窗口创建失败；运行期独占全屏请求记录错误并保留先前模式。

### R2 原生隐藏与逻辑窗口

- 策略在第一次显示后端构造和图形初始化之前确定，进程运行期间不切换，不持久化为项目或编辑器设置。
- Godot 管理的渲染窗口从创建到销毁保持 Win32 不可见，包括后端回退重建、布局恢复、浮动窗口和弹出子窗口；不允许先显示再隐藏。
- 创建及样式更新不能加入 `WS_VISIBLE`；显示、恢复、最大化及焦点相关路径不能突破策略。
- 保留 HWND、窗口尺寸与屏幕选择、Viewport 活动状态、现有渲染目标及交换链。不以 `Window.hide()`、移动到屏幕外、透明窗口或最小化实现该模式。
- 应用自身的 show/hide、Viewport 更新设置及显式最小化仍有原有逻辑意义。仅隐藏 Win32 可见性不使 `window_can_draw()` / `can_any_window_draw()` 返回 false；主动最小化或禁用渲染的应用不在持续绘制保证内。
- 不抢占桌面焦点，不限制或移动桌面鼠标。焦点查询不伪装为真实前台，应用自行按失焦暂停的行为不由此参数改写。

### R3 图形与执行策略

- 使用 Windows 显示后端与真实 Vulkan、D3D12 或 Compatibility 图形后端；保留消息泵、渲染循环、提交和 Present。现有真实图形后端回退规则保留并记录实际选择，不降级成 dummy/headless 掩盖错误。
- 隐藏运行前申请进程级执行速度 HighQoS，仅控制 `PROCESS_POWER_THROTTLING_EXECUTION_SPEED`，不改 timer-resolution 节流位或优先级。
- 申请失败时记录 Win32 错误码，图形初始化前非零退出。申请成功后正常退出和启动中止均释放覆盖，将该执行速度策略交回系统托管；释放失败记录警告，不弹窗。
- 保留既有编辑器按需重绘、低处理器模式、VSync、音频、网络、防休眠及优先级行为。此参数不添加新的性能策略，不承诺可见/隐藏性能相等。

### R4 编辑器子进程与原生交互

- 工具和游戏子进程、编辑器重启继承 `--offline`；每个新进程独立申请 HighQoS。任意用户自行启动的外部程序不自动改写命令行。
- 离线编辑器的游戏运行采用独立隐藏进程，运行期禁用自动嵌入和对应焦点恢复临时窗口，不写回用户的 embed-on-play 偏好。直接传 `--wid` 必须报错。
- 引擎控制的 `OS.alert()` 和窗口/图形初始化错误写入日志，不显示系统 MessageBox；原有致命错误路径仍非零退出，普通 `OS.alert()` 不额外强制终止进程。
- 原生文件选择请求不创建对话框，接受有效请求后返回 OK，并在主线程异步发送一次既有取消回调（`ok=false`、空文件列表，带 options 的版本保留回调形状）。
- 通用原生消息/文本输入对话框返回 `ERR_UNAVAILABLE`，不调用结果回调，不替用户选择任何按钮。Godot 自绘模态窗口仍受隐藏门控，自动化调用者须自行避免等待人工输入。

## Boundaries, errors and compatibility

隐藏范围是引擎管理的原生 UI，不包括调用者启动的终端、外部应用、Windows 自身错误报告或扩展直接创建的窗口。普通模式不受此策略影响。

Windows 桌面会话、可用 GPU 和可成功请求的 HighQoS 是前提。无桌面服务、显示器热拔插、锁屏/RDP 中断和独占全屏不作为首版可用性承诺。也不提供操作系统截图兼容性承诺。

## Acceptance scenarios

### S1 启动与参数

在同一可用 Windows/GPU 环境，分别启动隐藏编辑器、项目主场景、指定场景和导出模板，确认实际 DisplayServer 为 windows、渲染非 dummy。重复参数结果一致；参数位于用户参数区时不生效。交换冲突参数顺序均失败，配置隐含 headless 也失败。无项目回退的 Project Manager 不显示窗口。

### S2 窗口生命周期

监控启动至退出的 WinEvent 显示事件并周期枚举目标 PID 的 HWND。依次恢复编辑器布局、切换最大化/窗口化/普通全屏、修改无边框、创建和销毁子窗口、调整尺寸；没有显示事件或可见窗口，没有抢焦点或光标限制，客户端尺寸和 Viewport 尺寸有效且对应。可行时覆盖后端初始化回退重建。

### S3 绘制与截图基础

让非最小化场景持续改变可观察内容，等待实际帧绘制后从 Viewport 读取图像，确认新旧内容变化；记录绘制和图形提交/Present 证据，不能只看进程存活或 `_process` 计数。分别验证项目主场景和指定场景。显式最小化仍可暂停绘制，恢复后继续隐藏渲染。

### S4 HighQoS 与失败

成功启动时请求发生在图形初始化前。通过仅测试使用的注入点模拟 SetProcessInformation 失败，断言非零退出、包含 API/错误码且未初始化 GPU。模拟显示/图形创建失败，无系统对话框和无限等待；清理路径释放成功申请的覆盖。

### S5 子进程与交互

离线编辑器运行项目、指定场景并重启后，相关子进程同样隐藏且带参数；不注入 `--wid`，不启动嵌入显示及临时焦点窗口。原生文件选择返回一次取消；通用原生对话框返回不支持；不改写持久化编辑器偏好。

### S6 回归与平台边界

不传参数时主窗口、子窗口、原生对话框和嵌入游戏正常；原有 `--headless` 保持 dummy 路径。非 Windows 参数处理明确拒绝，公共 API 的默认实现不要求其他后端实现 Windows 功能。初始独占全屏明确失败，运行期拒绝后仍保留可用窗口状态。
